# Native Apple implementation

This directory contains the shared Swift 6 `FrankenTermKit` package and the native Xcode project for the first offline workspace-transfer slice. It is implementation source, not a signed or device-qualified terminal release.

## Entry points

Open `apps/apple/FrankenTerm.xcodeproj` with a stable Xcode supporting the iOS 26 SDK and Swift 6. The shared `FrankenTerm` scheme builds the iPhone/iPad application; `FrankenTermExport` builds the macOS companion (macOS 14 deployment floor). Both Apple applications link the local package and system cryptography, with no remote package downloads or generated project scripts. Linux validation additionally resolves pinned Apple Swift Crypto 4.5.2 and its locked Swift ASN.1 dependency to exercise the same maintained HPKE API. Development device signing needs the operator's selected team; no team or signing secret is embedded here.

The iOS app provides a native camera scanner, explicit transfer selection, bounded observation admission, authenticated package review, transaction-owned Keychain import, encrypted-file and ordinary public `.ftworkspace` import (including Open in FrankenTerm), and a machine/group browser preserving colors and ordering. Public documents need no transfer code and are clearly identified as unauthenticated, with no included private keys. Review and saved-workspace screens obtain credential availability, mandatory policies, host rejection, and dependent jump-route requirements from protected storage. It is single-scene until terminal/session ownership is integrated. It does **not** start SSH sessions, render a pretend shell, or execute imported auto-connect preferences.

The Mac companion opens a local `.ftworkspace` JSON document or builds one from **explicitly selected hosts in an SSH config**. Its searchable source chooser accepts up to 128 concrete aliases, reads their referenced public `.pub` identities and the user's `known_hosts`, and presents the resulting routes, host policy, and omissions for review. Local `Include` files support nested `*` and `?` patterns in lexical order, preserve the containing Host conditions, and resolve relative paths against the user's `~/.ssh`. The frozen source is bounded to 64 file reads, eight nested includes, 2 MiB, 16,384 lines, and 16,384 scanned directory entries; cycles, unsafe file permissions, nonlocal files and symbolic Include paths are refused. It preserves stable entity IDs between exports without evaluating commands, `Match`, environment expansion, DNS, or an SSH agent. Unresolved source semantics remain mandatory route blockers. This passive source uses an explicit default palette; it does not claim to capture live desktop themes or system configuration.

Configured-alias `ProxyJump` chains expand to at most three ordered transit hops, including each hop's public identities, account, port, and host trust. Unselected hops do not become machines, and transit does not activate their shell preferences. Explicit earlier prefixes override later hops' configured proxies while the first hop's own configured chain is preserved. User/port override syntax, unresolved aliases, repeated hosts, cycles, and excessive depth remain explicit blockers; an unusable chain is never truncated into a usable prefix.

Existing workspace documents support selection of one or more machine groups with their complete route, jump-host, trust, theme, and credential dependencies. Every canonical identity requires an explicit include-private-key or keep-reference-only decision before encryption. The companion accepts matching **OpenSSH Ed25519 and ECDSA P-256/P-384/P-521 key files**, including passphrase protection using **bcrypt with AES-128-CTR or AES-256-CTR**. The selected file's public algorithm and fingerprint must match before the passphrase prompt appears; actual private-key derivation must match again after decryption. Unlocking runs on the export actor, entirely in memory, with no decrypted temporary file or passphrase-bearing subprocess. Private source files are read only after their own file-picker choice. The companion releases excluded key material and reports concrete omissions and blocked routes. Selection changes invalidate the previous approval, code, and QR presentation.

**Save Selected Public Workspace** exports the reviewed public graph without private keys. Required source restrictions survive this format even though it has no archive metadata section. Mac and iPhone share the exact-byte, domain-separated file comparison value; checking it through a trusted separate channel does not make a self-asserted exporter authenticated. Existing filenames are not overwritten.

It offers live fountain-coded QR playback with periodic source replay, targeted page repair, 3/5/10-symbol-per-second timing, separately revealed transfer codes, encrypted `.ftairgap` saving, saved **lossless APNG**, and a **verified MP4** path. Each newly prepared transfer gets a fresh bundle identity; playback and saves reuse its exact frozen envelope. The phone lists unfinished page numbers matching the Mac's Repair menu and can restart one unfinished page while retaining verified pages and the selected source. The companion does not yet capture a running desktop FrankenTerm workspace automatically. Other encrypted key profiles, private RSA keys, certificates, and executable configuration remain unsupported.

**Encrypt Only for This Phone** adds the plan's recipient-bound mode. The phone displays a public, single-part `FTREQ1:UR:BYTES/` request. The Mac accepts it through a dedicated camera scanner or an explicitly selected local QR image, shows the recipient comparison, and requires confirmation against the phone before export. The fixed RFC 9180 Base-mode X25519/HKDF-SHA256/ChaCha20-Poly1305 suite encrypts to that ephemeral request. The phone then collects the ordinary encrypted animation or opens its local `.ftairgap` file, decrypts with its matching in-memory key, and still requires envelope comparison and source/contents review. Code mode remains the default and works without a Mac camera. Recipient-bound recordings are not independent recovery backups: losing the phone's active request key requires a new request and a newly encrypted export.

## Protected SSH authentication

`SSHAuthenticationBroker` implements use of the imported Ed25519 and ECDSA P-256/P-384/P-521 identities. A foreground request binds the selected installed-workspace revision, route, account, credential, actual presented host key, transport identity, and original SSH session identifier. The store checks the qualified transport profile, ordered credential policy, complete route dependencies, imported restrictions, protected-key availability, positive host pins, and durable local revocations before allowing a prompt. The same checks run immediately before signing and after the worker returns. Reimport, revocation, cancellation, backgrounding, and protected-storage failure discard delayed results. Request IDs are single-use; one broker owns at most one preparing or signing operation, including a cancelled operation that has not settled.

`SSHUserAuthenticationSigner` constructs the RFC 4252 public-key authentication preimage internally. It offers no arbitrary-message signing API, validates the complete OpenSSH container with the importer's canonical private/public binding checks, and returns the SSH algorithm-tagged signature blob. CryptoKit on Apple and maintained Swift Crypto on Linux perform the cryptography. ECDSA signatures use the required curve-specific SHA-2 hash and canonical positive SSH `mpint` encoding. The initial session-identifier profile accepts the 32-, 48-, and 64-byte SHA-2 sizes.

`AppleSSHCredentialSigner` reads only the exact app-owned Keychain account through a fresh user-presence context on one process-wide serial worker. The private container stays within that worker; its public result is a signature. The prompt has a 60-second cancellation deadline. Suspension/cancellation invalidates the context, and the worker slot remains occupied until synchronous native work settles. No key file, private-key return API, authentication queue, or reusable unlocked-key cache is introduced.

The optional `FrankenTermSSH` package now implements the nonblocking native channel and connection driver, with real-server interoperability evidence documented in its README. The workspace browser still needs the protected authentication adapter: canonical public-key discovery, exact broker-to-transport challenge binding, policy revalidation before publishing a connection, and cancellation when policy changes. Each jump peer requires independent verification. The app remains offline-only until that adapter, the native terminal artifact and scene ownership are integrated and qualified.

Nineteen focused signing/broker tests passed on Linux: an independent OpenSSL verifier checked all four real production signers, exact user-authentication fields, canonical ECDSA encodings and hash selection; actor tests exercised actual signatures completing after revocation, reimport, cancellation and suspension. Native Keychain and LocalAuthentication behavior still require an Apple SDK build and passcode-enabled device qualification.

## Bounded shared terminal output

The canonical Rust terminal now offers `Terminal::new_bounded_output`. It uses the existing parser, keyboard/mouse encoders, terminal modes and newline semantics with fixed preallocated byte and record rings. This mode creates no writer thread or unbounded channel and retains no extra `BufWriter` buffer. User input and terminal replies have independent budgets while sharing one ordered stream. The full outer input event is admitted or refused together, including mouse-wheel operations whose nested encoders flush repeatedly. A rejected mouse/focus event preserves logical button, motion and focus state. Bounded paste reserves its complete encoded size before adding either bracket delimiter and rejects executable control bytes.

The caller drives `drain_bounded_output` with a synchronous nonblocking sink. An exact accepted prefix releases its charge; a stalled sink retains it. `bounded_output_status` exposes local acceptance watermarks and whole-reply drops. `try_bounded_focus_change` exposes refused cleanup explicitly. `close_bounded_output` returns idempotent, content-free settlement separating accepted prefixes, bytes never offered, and an uncertain offered prefix after failure. No uncertain bytes may be replayed on a replacement transport. `writer_barrier` returns unsupported in this mode because downstream acceptance is not a remote flush acknowledgment.

This generic constructor removes the hidden unbounded writer; it does not by itself establish parser, image, screen or scrollback limits. The opt-in native model described below adds its own text profile and transfers whole parser replies to the Swift coordinator without a second user-input queue. Sixteen original focused Rust tests cover real parser replies, canonical keyboard/mouse encoding, transactional paste/focus behavior, saturation, partial/stalled sinks and failure uncertainty. They received independent source review but **were not compiled or executed**: the required RCH service/toolchain was unavailable. Required development proof is:

```sh
RCH_REQUIRE_REMOTE=1 RCH_NO_SELF_HEALING=1 rch --no-self-healing exec -- env CARGO_TARGET_DIR=/tmp/ft-bounded-terminal-output cargo test --locked -p frankenterm-term --lib terminalstate::bounded_output::tests -- --nocapture
```

Run the full `frankenterm-term --lib` suite through RCH afterward for desktop regression coverage. This constructor does not claim an iOS-buildable artifact or a native terminal release.

## Canonical native model and session ownership

The existing Rust terminal crate now exposes an opt-in `native` model and `native-ffi` C boundary. `NativeTerminal` uses the canonical parser, negotiated keyboard encoder, newline policy and FTSF capture. Input encoding is pure; whole parser replies remain charged in Rust until the existing Swift coordinator admits or deliberately drops their exact sequence. The C ABI exports generation-checked integer handles and caller-owned buffers, with one immutable acquired frame per session and explicit release. It never returns a Rust pointer or writes to a transport.

The native text profile bounds parser strings across feed calls, screens/history, retained graphemes, hyperlink metadata, replies and frames. Unsupported image execution and clipboard effects are disabled, and capability replies reflect that profile. Native limits do not silently truncate a model and continue presenting it as faithful. Desktop defaults retain the existing full profile. Native state is deliberately refused by the existing checkpoint format until that format can represent its replay semantics.

The optional [`FrankenTermTerminal`](FrankenTermTerminal/README.md) Swift product implements `NativeTerminalModel` against the actual header. `TerminalModelRuntime` joins it to the live session pump, source-bound keyboard, whole-reply handoff, owned-frame delivery and outcome reconciliation. Keyboard transactions span canonical mode sampling and coordinator admission, including composition and held-key cleanup. At most one consumer and one keyboard transaction can wait; no task or unbounded byte queue is created for each event.

Hidden terminals keep parsing and answering requests without creating new snapshots. A historical viewport evicted from scrollback becomes unavailable while the live model and answerbacks continue. Shutdown stops input admission, settles copied replies and joins active delivery before native release. `NativeSSHTerminalAttachment` provides the corresponding authenticated SSH source, a private driver capability, resize, close and retained acceptance accounting. The published UUID-based channel adapter remains compatible, but its UUID cannot take over the new capability-owned attachment.

Sixteen new portable runtime tests passed as part of the 401-case Kit suite. They exercise the real coordinator and ownership logic with an explicitly opaque injected model; they do not claim Rust execution. The optional Swift binding compiled with warnings treated as errors against the actual C header, and Clang accepted the header/layout assertions as C11 and C++17. The new Rust model/FFI tests are source-reviewed but remain uncompiled and unexecuted because RCH is unavailable. No C-linkable Rust artifact or Apple qualification is implied by these checks.

## Owned shared terminal frames

`frankenterm_term::render::capture_terminal_frame` captures an actual resident viewport from the canonical terminal engine into an owned FTSF version-one full replacement. The desktop mux mirror now uses the same `MirrorColor`, `MirrorCell` and `MirrorRow` conversion from the terminal crate. Complete graphemes survive capture, including strings longer than the former eight-bit text-length field could represent. The capture borrows resident lines, checks geometry, cell counts, UTF-8 spans and hyperlink sizes before allocating its output, and neither parses a second terminal stream nor causes replies, hyperlink rescans, image copies or cold-scrollback reads.

The frame binds the transport and channel UUIDs, route revision, terminal sequence, frame/geometry/palette/font revisions, stable viewport rows, cursor, complete palette and semantic cell attributes. Its fixed-width little-endian tables contain checked spans into one UTF-8 pool; no pointer or Rust object layout crosses the representation. Initial limits cover 512 rows/columns, 65,536 occupied grid positions, one MiB of text, 4,096 links and eight MiB per frame. Images, bidirectional or RTL row layouts and double-size lines fail explicitly until their native representation is implemented. A full replacement avoids requiring an incremental-delta recovery protocol for this first producer. The default Legacy grid is supported; opt-in Page storage is rejected before its lazy legacy view can allocate unbudgeted text and attributes. Page capture requires a bounded native adapter.

`TerminalRenderFrame.decode` independently validates the representation, exact expected source, contiguous table/span layout, UTF-8, attribute codes and resource limits before publishing Swift values. Source identity is provided by the authenticated session owner; a decoded frame grants no authority to connect or send input. The portable slot owner tracks exact leases for the three GPU resource sets, so a stale completion cannot release a newer frame's buffers.

Ten new Rust capture and desktop mirror regression tests cover real parser output, ANSI attributes, split UTF-8, long graphemes, links, sequence consistency, palette/alternate-screen changes, admission bounds, unsupported modes/storage and capture without terminal replies. They are source-reviewed but still require compilation and execution in the authorized RCH build environment. The independent Swift decoder, shader packing, shaping map and slot ownership tests run with the existing portable package suite.

## Native Core Text and Metal display

`NativeTerminalRenderView` consumes the owned canonical frames. Its asynchronous initializer loads the checked-in desktop `background.metal` and `text.metal` resources, compiles their pipelines on one bounded worker and shares the resulting immutable pipelines. The Xcode application bundles those original files directly. The production Swift packer uses the shaders' actual 256-byte uniform allocation, four-byte background cells and 24-byte glyph records.

One serial preparation worker performs full-row Core Text shaping, maps UTF-16 shaping indices back to canonical grapheme cells and rasterizes glyphs into bounded grayscale/color atlases. Shared glyphs are clipped at terminal paint boundaries, including a block cursor covering one column of a wide cell. Palette/RGBA colors, bold/italic/half intensity, reverse video, concealment, underline styles, overline, strikethrough, super/subscript placement, color glyphs and cursor/text blinking are implemented. The v1 LTR contract is explicit; remaining RTL or cross-cell reordered clusters return unsupported. Atlas, glyph and instance overflow returns a capacity failure rather than a partial terminal image.

Each surface retains one replaceable pending full snapshot, one preparation operation and at most one submitted GPU command. Three exact resource leases prevent writes to unfinished GPU work. A process-wide six-slot reservation bounds atlas and buffer allocations to approximately 50 MiB, including resources retained by unfinished commands. Rendering uses an on-demand display link and discrete blink timers. Synchronized-output frames advance semantic state without presenting partial updates. Retirement invalidates callbacks while exact GPU completion retains ownership of submitted resources.

`NativeTerminalView` combines this display with the UIKit text responder. Successful matching-generation GPU completion publishes its caret and actual font/foreground to the input view. Resize, font changes, offscreen cursors and deactivation invalidate old geometry. New input and paste admission stop until a newer matching projection arrives; temporary layout invalidation preserves uncommitted composition. Replacement keyboard sessions must use the same source after old cleanup settles, and retain the currently displayed appearance. `onViewportChange` returns a source-bound measured grid proposal; the session owner must apply canonical terminal and SSH PTY resizing and submit revised frames. Configuration changes advance `fontRevision`, which must match the semantic frame.

This is an implemented reusable native surface, not an enabled connection in the workspace browser. The bounded SSH driver, model ABI and Swift session owner now exist; the C-linkable iOS Rust artifact, protected workspace authentication adapter and native scene hookup remain outstanding. Apple SDK typechecking, actual shader compilation and device pixel/IME/lifecycle qualification have not run here.

## Native terminal text input

`NativeTerminalInputView` is a UIKit `UITextInput` responder backed by the existing bounded `TerminalKeyboardSession` and `TerminalInputCoordinator`. Its local TextKit document contains only uncommitted IME text, with selection, tokenizer, delegate notifications, grapheme-safe deletion and UTF-16 boundary checks. `NativeTerminalCaret` ties candidate-window geometry to the same immutable source and monotonically identified layout as the visible renderer. Retiring the view, losing scene activity or replacing focus discards unsubmitted composition and settles source-owned cleanup.

The accessory row provides Esc, Tab, arrows, and one-shot/locked Ctrl and Alt. Hardware printable text follows UIKit's text/IME path once; terminal control presses and software Return/Tab use the canonical encoder. Held keys are released through reserved cleanup before composition begins, and failed key-up admission cannot silently forget a held key. The shell can present a bounded paste preview and confirm its exact keyboard/focus-bound request. Only an encoder implementing the source's current paste policy can enable paste; the UI supplies no bracketed-paste mode and no fallback ANSI implementation.

`NativeTerminalInputSurface` supplies the SwiftUI adapter. Its owner must provide an authenticated `TerminalKeyboardSession`, canonical Rust encoder, and matching renderer caret, and finish the old focus handoff before installing a replacement session. The adapter does not create a transport or enable input in the offline workspace browser. Fifteen portable routing/admission regressions passed, including composition cleanup under saturated ordinary input capacity. Nine UIKit-gated tests cover actual text positions, delegate callbacks, composition, caret identity, canonical Return/Tab routing, retirement, and input/paste blocking across invalidated or replayed caret projections; those tests have only passed syntax parsing here and require an Apple SDK test run.

## Implemented invariants

- `WorkspaceStore` serializes the journal, Keychain ownership, and catalog publication under an exclusive persistence lease. Before deleting staged or retired identities, recovery reaffirms the selected catalog's **durability**. Reading renamed bytes after a failed fsync alone does not authorize deletion.
- Import confirmation is tied to an exact decrypted candidate and previously reviewed saved revision. Existing local revocation denies resurrection from an old recording. Missing device keys can be restored from the same backup without duplicating surviving keys.
- The durable catalog remembers accepted bundle/transfer identities, rejects conflicting reuse before staging keys, and requires separate local approval to restore an earlier accepted export. Bundle identities are bound to their exporter across workspaces; transfer IDs and envelope digests cannot be rebound across namespaces. Canonical host-key revocations and mandatory trust requirements survive renamed trust records, replacement, and approved rollback. Migrated transfer identities use the same journal; recovery checks the accepted identity as well as workspace bytes.
- Catalog version four migrates the original single-candidate store, published version-two import history, and published version-three endpoint denials. Every accepted identity, digest, first revision, and global endpoint rejection is preserved. Additional effective-host alias denials and mandatory host-policy requirements survive replacement and approved rollback. The native browser obtains actual Keychain availability and durable local policy in one revision-consistent snapshot, and clears availability on deactivation or protected-storage failure.
- Host-key rejection persists by canonical host and port, independently of imported record IDs. DNS/IDNA, IPv6, and mapped IPv4 spellings cannot remove it. Negative fingerprints take precedence over algorithm labels and positive pins, including a presented certificate authority; certificates themselves still require a future qualified implementation. Every jump hop contributes its own readiness requirements.
- Credential reuse binds both the canonical public fingerprint and algorithm. An import without private material cannot relabel an existing Keychain identity. Matching aliases share material while retaining route-specific candidate order and authentication policy. A blocked candidate does not prohibit a separate permitted candidate.
- Public and encrypted imports reuse compatible protected identities across installed workspaces after checking vault metadata under the same storage lease. Reimporting an unchanged public document can attach a key acquired later while preserving its first acceptance and enforcing the reviewed revision. Replacing one workspace never retires an identity still referenced by another; duplicate private records are not created for shared canonical identities.
- Passive SSH export supports ordinary and OpenSSH v1 hashed `known_hosts`, including nonstandard ports, exact host-key aliases, numeric IPv6 lookup, and revocations. Positive pins require the source lookup to match; negative policy also survives canonical endpoint spelling. Unrelated valid hashes do not disable routes. Malformed hashes, unsupported certificate authorities/markers, and unreadable trust sources cannot silently remove required policy. Source size, alias count, pattern work, and HMAC comparisons are bounded.
- The manifest uses the comprehensive plan's ordered `credential_refs` and `authentication_methods`. Strict core allowlists exclude untyped settings; bounded optional namespaced extensions are discarded before persistence or re-export. Route readiness evaluates every jump, available identities, host pins/revocations and required capabilities independently. The current-plan example is an executable fixture, including mux route policy; this does not implement a mux transport.
- The published catalog contains public manifest bytes and account references, not private containers. `connectLater` remains persisted through restart. Keychain items are device-only, passcode-bound, user-presence protected, nonsynchronizable, and created without overwriting existing accounts.
- `OfflineRestore` distinguishes ciphertext reconstruction, authentication, review, commit, and recovery. Wrong-code retries preserve ciphertext. Suspension discards decrypted previews and retires observation generations. An uncertain publication is reconciled, not blindly repeated.
- Recipient mode binds the exact canonical request ID, public key, advertised envelope limit, and request digest into HPKE setup and the authenticated FTAG header. Unknown modes, malformed headers, wrong requests, over-limit envelopes, and cross-mode fallback are rejected before publication. Only one recipient request exists in a restore actor. Its private key never enters a status, workspace, or persistent store. Backgrounding retains that key only in process memory and requires explicit request resume; close, reset, completed import, or process termination ends its availability. Decrypted review and prior approvals do not survive suspension.
- Native recipient approval binds the complete 32-byte request digest captured by the rendered confirmation control, not merely its displayed abbreviation or a mutable Boolean. The export engine rechecks that digest before sealing. A delayed confirmation, scanner callback, or encryption result cannot silently approve a different destination.
- The HPKE adapter delegates the KEM and key schedule to maintained CryptoKit on Apple and Swift Crypto on Linux. It bounds inputs and performs native X25519 agreement before setup to reject an all-zero result on both sender and receiver paths, including noncanonical low-order aliases. Each local sender context seals once at sequence zero; cancellation cannot return a completed result.
- Recipient envelope caps are checked before allocating an optical receiver. An unrelated destination, wrong mode, or malformed completed envelope discards that selected source and fences its observations while preserving the phone's request for another response. Decrypted packing buffers and owned session keys are cleared where Foundation permits; a private-key copy does not cross the awaited storage-review boundary. This does not guarantee erasure of every copy made by platform cryptography.
- Mac recipient capture uses bounded video buffers and serial Vision QR detection, independent of camera-specific metadata support. It discards late frames, examines at most four frames per second, limits image dimensions and extent, rejects ambiguous requests, and stops after one result or two minutes. Delivery rechecks actual application activity, window attachment, and generation. It records no images or audio.
- Closing the Mac export window clears visible material and the engine's keys, cancels work, and serializes reopening behind final cleanup. Operation identities fence every asynchronous source, key, export, and recording completion. On iOS, protected-storage refreshes run separately from lifecycle transitions, so a delayed catalog read cannot delay suspension or cancellation. Active request display and camera collection keep the screen awake while preserving the user's prior idle-timer setting.
- A QR observation cannot silently change the selected source. Eight bounded strings feed one consumer; there is no task-per-camera-frame fanout. The scanner does not open QR URLs or retain camera images.
- Live playback periodically repeats rotating source fragments while fresh repair sequence numbers continue increasing, so late arrivals can recover even if mixed repair frames are missed. The phone can reset one unfinished page while retaining verified pages and fencing queued callbacks from before the reset.
- Live display, APNG, and MP4 share one fixed QR version-22, level-Q profile with ECC boosting disabled. Its 105-by-105 matrix and four-module quiet zone remain constant across short source frames and long-running repair sequences. The profile admits the complete 767-character conservative framing bound (763 for the current sender), including the longest wrapper and sequence number. A pinned, unmodified Nayuki encoder supplies the matrix; shared grayscale rendering uses whole-module integer scaling with no interpolation.
- Private-key validation binds the manifest algorithm and fingerprint, outer public blob, inner public point and derived private identity. Archive construction and decoding validate bounded portability findings and inactive annotations against retained workspace entities.
- Encrypted source-key admission bounds the PEM/container extent, public-key profile, bcrypt salt (16–64 bytes), work factor (1–64 rounds), passphrase (1–1,024 UTF-8 bytes), and AES output before expensive work. One selected file owns one request and at most five attempts. Cancellation, replacement, and deactivation retire that request; stale callbacks cannot affect a newer selection. A completed key installation retains rollback ownership until the foreground UI accepts it, covering cancellation after the native KDF returns. Swift/platform allocations can retain copies, so clearing owned buffers does not claim forensic memory erasure.
- The source unlocker uses pinned upstream OpenSSH bcrypt/Blowfish, a per-call maintained SHA-512 primitive, and Apple CommonCrypto AES-CTR. It validates every decrypted component and all 0–15 bytes of AES container padding before repacking the clear inner OpenSSH container under FTAG encryption. Archive decoding still refuses an encrypted inner key. Source files are never rewritten; the source passphrase is never embedded in the archive.
- Portability records must reference retained entities; required unresolved conditions block their affected routes and dependent hops. Only registered boolean/opacity public desktop annotations may enter the catalog. Unknown optional opaque values are discarded with a content-free notice; unknown required values reject. Older catalogs are sanitized and durably migrated before publication, without changing accepted export identities or allowing failed migration to delete journal-owned keys. Network imports still require the current manifest format.
- The Mac removes the QR surface and invalidates pending raster results before revealing the code. The animation encoder accepts **only ciphertext**, not an application-window screenshot or a transfer code.
- Saved recordings contain every systematic symbol and a repair set. Each APNG frame, timing, loop metadata, and reconstructed envelope are verified before its final name is published. Existing destinations are not overwritten. Larger recordings are rejected before rendering rather than truncated; the initial saved path caps 256 frames, 1024-square raster input, and 128 MiB output. Live transfer remains available for larger bounded envelopes.
- The MP4 writer consumes a typed ciphertext-only source, encodes a bounded 1024-square H.264 stream at 30 fps, then decodes every output frame and verifies its QR payload, presentation time, hold duration, and reconstructed envelope. It caps 1,024 symbols, 9,000 video frames, 256 MiB, and a cooperative 600-second deadline, uses a bounded pixel-buffer pool, and excludes audio and custom metadata. Publication refuses existing destinations, uses an exclusive rename, and synchronizes the file and containing directory. A post-publication durability error retains the valid file and is reported distinctly. Native SDK/codec and physical-camera qualification remain outstanding.
