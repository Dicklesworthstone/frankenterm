# Native Apple implementation

This directory contains the shared Swift 6 `FrankenTermKit` package and the native Xcode project for the first offline workspace-transfer slice. It is implementation source, not a signed or device-qualified terminal release.

## Source omissions survive the default Mac export

The default **This Mac's FrankenTerm machines** source now carries a typed completeness report from the Rust helper through the Mac's review, group/machine selection, encrypted FTAG archive and installed workspace. Previously the helper's diagnostic notes were dropped by this path. Omitted routes and machines, desktop working-directory/icon/gradient settings, and the inventory source's limits now remain visible. Findings for removed entities attach to a surviving machine, group or workspace so narrowing the selection cannot discard them accidentally.

The existing Send action shows the relevant omissions and offers **Send Available Settings to iPhone** when the selected source is incomplete. Required route and trust policies keep their existing blocking authority. Informational omissions do not invent new authentication permissions or turn every route into a denial. An inventory snapshot explicitly identifies that it does not capture live desktop overrides or running sessions.

The helper's version-two report and legacy version-one notes share a strict duplicate-key-rejecting parser. Reports are limited to 1,024 findings and 256 KiB, with bounded text, valid surviving entity references and no partial-prefix fallback. Local private-key file hints stay outside the exported public manifest. Rust and Swift regressions include helper-to-QR-to-install preservation, selective scope, required policy, legacy notes, malformed envelopes and all-or-fail limits; execution still requires RCH and Swift/Apple toolchains.

## Conditional pane resizing and observed terminal rows

With rebuilt codec-v72 servers and native artifacts, phone size changes and desktop-size restoration carry the exact observed server incarnation, durable pane UUID and live registration. The server checks that witness before admitting work and retains the original pane guard through the resize callback. A reused numeric pane ID cannot redirect that request to its replacement. There is one in-flight resize and one replaceable unsent successor per pane, a 32-pane connection budget and a five-second original deadline. Refusal, an ambiguous result or expiry never downgrades to a numeric resize or automatically replays the effect.

The server reports **Enqueued**, because the terminal's asynchronous resize/reflow worker may still be running. The phone keeps its original desktop-size recovery record until a post-acknowledgment pane listing actually shows that geometry. If observation expires, recovery stays available for a later deliberate restore. This operation does not establish a controller lease, arbitrate with desktop resizing or compare an expected layout revision; older supported dialects retain their existing numeric resize behavior.

On codec v69 and later, the phone also requests a correlated render observation and fetches missing rows against that exact sequence and line layout. Delayed replies cannot overwrite rows changed by newer output or apply coordinates from a previous size, alternate screen or view visit. Unchanged rows can still finish loading while other rows receive output. Refused reads retain the last display and use the existing bounded retry path; successful unchanged observations clear the waiting indication without forcing a repaint. Image-reference tails are decoded completely before sequence metadata is read, although image rendering remains unsupported. These are row-coordinate guarantees, not the complete palette/mode render snapshot described in the comprehensive plan.

Regression sources cover canonical codec agreement, stale pane witnesses, deferred admission/retirement, ambiguous callbacks, coalescing/deadlines, observed restoration, delayed rows, hide/reopen, busy recovery and metadata replies crossing newer size changes. Rust execution and Apple/device qualification remain outstanding in this environment.

## Attach to the existing desktop mux over SSH

The phone's default mux command is now `ft mobile attach --stdio --no-auto-start`. Install the updated `ft` on the SSH host; an explicit route command continues to take precedence. The command connects to the already running mux using `--socket`, `FRANKENTERM_UNIX_SOCKET`, or that platform's ordinary FrankenTerm runtime socket. This removes the previous Linux-specific runtime path and dependence on a particular `nc` implementation.

Attachment runs before async runtime, workspace, configuration and logging initialization. It verifies the socket and peer belong to the SSH account, then forwards the existing binary mux protocol with 32 KiB buffers in each direction, bounded stalled writes and bounded final draining. Closing input half-closes the mux stream and still delivers its final replies; losing the server retires the relay even if SSH stdin stays open. It does not start a mux, create a terminal or fall back to another socket. Access remains that of the authenticated SSH account; device-scoped Via Mac enrollment is a separate unfinished feature.

New tests exercise the actual CLI and canonical codec frames, both EOF orders, large bidirectional payloads, rejected input with a final reply, socket selection and failure without startup side effects. Rust execution and Apple/device qualification have not run for this command in this environment.

## Two live machines on iPad

In an iPad window at least 720 points wide, **More → Split with Another Machine** opens two stable machine slots. The existing navigation/composition barrier transfers focus to the chosen machine before the pair is shown. Only the focused slot accepts keyboard, pointer, paste, command-composer or remote-size actions; the other continues rendering its existing session and fits that remote grid locally. Tap its view or heading to transfer focus. Choosing a third machine replaces the focused slot without duplicating the other session.

A manual or ended route still requires its normal **Open Terminal** or **New Session** action. Splitting does not grant connection or shell-creation consent. A replacement connection in the observing slot remains a prompt until deliberately focused. Narrowing the window collapses to the focused slot while retaining the pair; widening brings it back. **Close Split** ends the extra presentation, not either remote session. Hidden sessions continue consuming output, and the existing global GPU-resource limit remains unchanged.

Focus loss drops unsent viewport proposals, disables mux geometry control, clears stale selection controls and retires local input through the existing handoff. An admitted resize still owns its asynchronous resources until settlement. Local grid fitting rebuilds caret and selection geometry without changing the semantic font revision.

Portable layout/resize cases and hosted renderer/controller regressions cover stable slots, narrow/wide transitions, live output from both SSH channels, stale input refusal, focus-specific input, unchanged companion PTY geometry and manual session policy. These new tests have syntax/source checks but require Swift and Apple execution; the historical simulator results below do not qualify this split implementation.

## Durable mux pane continuity

Reconnecting a saved mux pane now requires a fresh match of the server incarnation, durable pane UUID and registration ID. The mobile Rust client exposes the existing v71 passive identity query through the C ABI and Swift adapter without subscribing, typing, resizing or changing the desktop's active pane. It bounds concurrent queries to eight, expires them after five seconds and ignores retired replies. Showing a pane rechecks a previously learned identity before attaching.

The phone persists this complete witness with its selected pane and saved phone-size metadata. Moving the same pane between tabs or windows preserves continuity. A restarted server, replaced registration, unavailable witness or legacy numeric-only bookmark leaves the connection open with no pane selected; the person chooses from the current inventory. First attachment without a saved bookmark can still show the desktop's active pane. Unconfirmed input remains disclosed and is never replayed. Numeric pane IDs alone cannot restore a saved phone size.

Display subscription and permission to control remote geometry are separate: a visible observer can continue receiving output after size control is disabled. Disabling it restores a size this connection adopted, including when the first show did not finish. Enabling it cannot broaden a view-only or input-only connection. This uses the existing geometry protocol; server-enforced controller leases and atomic registration-conditional geometry mutations remain separate work.

New Rust codec, C-boundary, Swift persistence and SSH adapter regressions cover bounded queries, deadlines and late replies, removal/reuse, unchanged and moved panes, replacement, unavailable identities, legacy records and size-control transitions. The XCFramework builder now checks both terminal and mux exports against the public header. These additions have source and syntax checks; they still need RCH Rust execution and Apple-hosted integration runs.

## OpenSSH user certificates in machine exports

`ft mobile export` and `ft mobile source` now preserve explicitly configured `CertificateFile` identities for the existing phone certificate importer and SSH signer. Matching declarations remain additive and ordered across user/system configuration. Certificates precede independently configured raw-key candidates, carry their exact signed public blob and `ssh_user_certificate_v1` requirement, and retain the raw subject fingerprint for protected-key matching. Renewing a certificate changes its offer identity and the configuration revision. A certificate alone never invents a private-key filename or a raw-key fallback.

The exporter verifies OpenSSH v01 user-certificate signatures with the existing OpenSSL dependency: Ed25519, RSA with SHA-256/SHA-512, and NIST P-256/P-384/P-521. Parsing bounds and canonical key, principal, option and signature checks match the phone's supported profile. Each blob is capped at 32 KiB, public certificate sources at 256 files and 2 MiB, and the complete exported certificate set at 1 MiB. Exact duplicate certificates are deduplicated before the combined eight-candidate route limit. Missing, unreadable, malformed, over-budget or unverifiable certificate sources block the complete route policy without publishing a usable prefix. Unsupported path substitutions remain explicit blockers.

The phone still checks validity time, account principals, critical options and PTY/forwarding permissions before authentication; a verified CA signature does not establish that a remote server accepts that CA. Host certificates and host-CA trust remain outside this user-certificate implementation. New regressions cover independent OpenSSH certificate fixtures, renewal, source ordering, malformed signatures, candidate and byte limits, and preservation of private-key inclusion consent. Rust compilation and test execution still require the repository's remote RCH runner.

## Complete SSH identity policies in machine exports

The Rust machine-inventory exporter now admits each route's entire ordered public-key candidate set before publishing credentials or private-key file hints. Eight distinct identities are supported; duplicate references to the same key still share one credential. A ninth distinct key, an unreadable or over-budget source, an unresolved explicit identity, or malformed/multiple-key sidecar blocks the route instead of leaving a usable prefix. Mux copies retain the same mandatory refusal, and jump-route readiness propagates it to dependent connections. Other complete routes remain available.

Public-source discovery retains explicit failures at its existing 256-file, 2 MiB aggregate and 64 KiB per-file limits. A missing default public sidecar is ignored only when the corresponding private filename is also absent; checking that requires filesystem metadata, never reading or unlocking private key bytes. Resolve the missing public metadata or deliberately narrow the source identity policy before preparing the affected route. These refusals cannot silently become password fallback.

Regression coverage includes candidate deduplication and boundaries, unavailable jump dependencies, malformed and missing sidecars, private-only default identities and legitimate absent-default fallback. Scoped Rust parsing/formatting and independent source review passed. The required remote test command could not start because `rch` is unavailable; these regressions still require execution through the repository's Rust proof path.

## Rendering under battery, thermal and memory pressure

The native terminal now responds to Low Power Mode and thermal-state changes through its existing display scheduler. Nominal conditions request a 120 Hz ceiling (60 Hz preferred), fair thermal conditions cap that ceiling at 60 Hz, Low Power Mode or serious heat cap it at 30 Hz, and critical heat caps it at 15 Hz. These are presentation requests, not measured frame-rate guarantees. Decorative text and cursor blinking stop in their visible phase while conserving power; cooling restores them from the retained screen without requiring new terminal output.

Memory warnings release idle worker-owned GPU caches and reconstructible accessibility output. Prepared frames and submitted GPU commands retain their exact resources and allocation leases until completion. The latest terminal screen, pending output, parser state, input order, SSH connections and remote geometry remain owned by their existing subsystems. Cache reclamation does not immediately schedule work to refill the cache.

Four portable policy/resource-lifetime regressions and two hosted Rust-to-Metal regressions accompany this implementation. They still require execution with the Swift and Apple toolchains; source review and whitespace checks alone do not establish device behavior. The native-app and device-qualification beads remain open.

Imported auto-connect settings and phone-local preferences remain intact; they cannot approve themselves. Identical recordings and changed exports both re-arm the gate without duplicating identities or weakening host policy.

Entering strict offline restore joins pending connection approval before persisting the gate for every saved workspace. Publication failures do not authorize a connection; retries reaffirm the durable write. ## First-time host-key verification

When an imported direct SSH or FrankenTerm mux route has no trusted host key, **Keys → Check Host Key** performs a bounded SSH key exchange and closes the connection before offering an account, key, password or MFA answer. Compare the complete displayed fingerprint with the server administrator or an existing trusted connection, then explicitly confirm the independent comparison and choose **Trust Verified Host Key**. Receiving the fingerprint from the same untrusted connection alone does not establish the server's identity.

The phone saves a public pin separately from the original imported manifest and envelope digest. Approval retires this workspace's live sessions, creates a new saved revision and keeps it offline until a fresh **Connect**. Reviews cannot cross an app lifecycle change, workspace replacement or another store instance. Existing imported or local pins cannot be replaced through this first-use path, and late revocations, failed-write process-local refusals and mandatory source policy still win.

Local pins survive relaunch and unchanged source-policy reimports. An endpoint, alias or trust-policy change deactivates the old local pin and requires a new review; newly imported positive pins take precedence. Destinations behind jump hosts still require imported verified trust. Catalog versions 1–7 migrate to version 8 without inventing positive trust or changing authenticated import history.

## Phone-generated SSH identities

**Keys → Create Phone SSH Key** creates an independent Ed25519 key in protected storage. Generation preserves existing sessions and does not connect or change a server. **Copy Public Key** copies only its OpenSSH public line, locally with a two-minute clipboard lifetime. Authorize that line on the intended server account through your existing trusted administration method, then use **Choose Routes**. Remote enrollment automation and Secure Enclave keys remain separate work.

A reviewed choice replaces one route's public-key candidates, including use as a jump host. Host trust, permitted password/MFA methods and required policies still apply; certificate-restricted identities cannot be replaced by a plain key. Changing a choice disconnects this workspace first and requires a fresh **Connect**. Generation alone does neither.

The imported manifest/history stay unchanged. Catalog version 8 retains separate public key metadata and route-policy witnesses alongside locally verified host pins. Changed routes require review after reimport. Removed routes retain their choices in case they return; the user can explicitly forget them. Local revocation uses the existing fingerprint and session-retirement path. There are at most 16 generated keys and 256 route choices per workspace. Portable compiler checks do not establish Apple Keychain, server interoperability or device qualification.

## Entry points

Open `apps/apple/FrankenTerm.xcodeproj` with a stable Xcode supporting the iOS 26 SDK and Swift 6. The shared `FrankenTerm` scheme builds the iPhone/iPad application; `FrankenTermExport` builds the macOS companion (macOS 14 deployment floor). Both Apple applications link the local package, system cryptography, and pinned Apple Swift Crypto 4.5.2's CryptoExtras for RSA. Swift ASN.1 remains locked with that dependency. Existing Apple Ed25519, ECDSA, HPKE, and archive encryption use CryptoKit/CommonCrypto; RSA uses CryptoExtras' maintained BoringSSL implementation. Linux also uses Swift Crypto for the existing CryptoKit APIs. Development device signing needs the operator's selected team; no team or signing secret is embedded here.

The iOS app provides a native camera scanner, explicit transfer selection, bounded observation admission, authenticated package review, transaction-owned Keychain import, encrypted-file and ordinary public `.ftworkspace` import (including Open in FrankenTerm), and a machine/group browser preserving colors and ordering. Public documents need no transfer code and are clearly identified as unauthenticated, with no included private keys. A newer export of a saved workspace replaces it with one tap on **Replace**. One line above the button names the saved workspace, how many settings change and how many of those are connections or host keys, and says if machines are removed or an older version returns. Opened over a live terminal, the restore first ends the sessions with one tap on **Disconnect Sessions and Restore**, with one line naming the workspaces whose sessions it ends. After **Done**, or after closing the restore, those workspaces remain offline until a deliberate **Connect** action. Every changed value is under Details. Review and saved-workspace screens obtain credential availability, mandatory policies, host rejection, and dependent jump-route requirements from protected storage. **Keys** on a machine page lists the workspace's SSH keys and the host keys it trusts. **Revoke on This Phone** blocks a key's fingerprint in every workspace on the phone. **Stop Trusting on This Phone** blocks one host key from that host and port in every workspace, including later imports. Each asks once, naming the workspaces whose sessions it ends, and then ends them; neither changes the Mac or the server. If the phone cannot save a host-key block, the key stays refused until FrankenTerm quits, and Keys says the block was not saved and offers **Save Block** to try again. A ready direct-SSH route offers **Connect**. That opens the live workspace screen on that machine: the real Rust model, drawn by Metal in the machine's theme and the bundled Pragmasevka Nerd Font, with the native keyboard. The machine/pane rail, its menus and two-finger swipes switch between the group's machines. With a hardware keyboard, ⇧⌘] and ⇧⌘[ switch to the next and previous machine, and ⌘] and ⌘[ step a mux machine's panes, while a terminal has the keyboard. Switching machines keeps the software keyboard up, so neither terminal changes size. A machine, or a mux pane, that prints while it is off screen gets a dot on its chip until it is shown again. Output in its first 3 s off screen does not count: when the keyboard does leave with it (a hardware key hides the software keyboard), its terminal is resized and its shell redraws. Each connected machine keeps its own session, and Kit's navigation focus barrier gives the single keyboard to exactly the selected one. Machines that are not on screen keep reading output but stop building display frames. Dragging the terminal down scrolls back through its history (256 lines), which stays put while output continues; a button or any typing returns to live output, and each machine keeps its place across switches. Keys typed while history is shown are not sent. A server that stops answering (a dropped network, a sleeping or hung host) is reported as a lost connection within about 30 seconds: after each quiet 10 seconds the connection sends one SSH keepalive that asks for a reply, and two further silent intervals end it. When the phone's network changes (Wi-Fi to cellular, or the network back after a gap), each live connection sends a keepalive at once and is reported lost if 10 seconds pass with no answer, so one stranded on the old network reconnects sooner. Changes a moment apart wait out the 2 seconds SSH needs between keepalives, so a connection that answers is not mistaken for a lost one; a keepalive SSH holds back in that time counts as not sent and goes once it can. A server that answers is never disconnected for being idle, and a dropped connection reads as lost rather than as closed by this device. **Select Output** shows the received viewport as read-only text to select and copy (copies stay on the device and expire after two minutes). **Paste** shows the exact clipboard text and its destination; nothing is sent until it is confirmed, and no Return is added. A tap on a link shows its full address beside it, with **Open** (web and mail addresses only) and **Copy Link**; a tap anywhere else puts it away and opens nothing. That covers links a program prints (OSC 8), on a direct session or through a mux pane, and web addresses in plain output, found by the desktop's rules, even where they wrap onto the next row. A link a program prints covers all of its text. An address that runs off the bottom of the screen is not offered until the rest of it is shown. Leaving the screen keeps its sessions running until they are disconnected. A new launch can return to the terminal that was on screen only while its saved workspace retains a deliberate connection approval. Offline restore re-arms the gate and clears the detached terminal's bookmark. Leaving that terminal, or disconnecting its machine, makes the next launch start at the workspace list. Each machine's theme can be changed on the phone: a **Theme** button on the machine page and in the live terminal opens a searchable picker of the workspace's own themes, FrankenTerm's twelve distinct hue themes and every built-in color scheme (the catalog `ThemeCatalog.json`, written by `ft mobile themes` and kept current by a Rust test). A pick re-themes a connected terminal at once and is kept on the phone per workspace and machine. When a workspace first arrives, machines that would look alike get distinct themes automatically, using the desktop's rule (the first free hue 22 degrees clear of the others); a machine added later never recolors the rest. The app is single-scene. Once **Connect** approves the saved workspace revision, showing a group marked auto-connect signs in its opted-in machines in the background. A machine's mux route attaches to its running FrankenTerm panes (see M0 below); when no mux answers there, the machine gets a new shell on its direct SSH route, under that route's own session policy.

At launch the Mac companion loads **this Mac's FrankenTerm machines**: it runs its bundled `frankenterm-machines` helper (built by `scripts/build-apple-machines-helper.sh` and copied in by the FrankenTermExport target; without it, an `ft` with `ft mobile source`), which reads `machines.toml` and reports each credential's private-key file. The companion selects every group and reads, validates and includes those keys itself; a passphrase-protected key waits for **Choose Matching Key…**. The user still approves the included keys before **Prepare Encrypted Transfer**. It can also open a local `.ftworkspace` JSON document or build one from **explicitly selected hosts in an SSH config**. Its searchable source chooser accepts up to 128 concrete aliases, reads their referenced public `.pub` identities and each route's effective `UserKnownHostsFile` and `GlobalKnownHostsFile` lists, and presents the resulting routes, host policy, and omissions for review. The frozen source is bounded to 64 file reads, eight nested includes, 2 MiB, 16,384 lines, and 16,384 scanned directory entries; cycles, unsafe file permissions, nonlocal files and symbolic Include paths are refused. It preserves stable entity IDs between exports without evaluating commands, `Match`, environment expansion, DNS, or an SSH agent. Unresolved source semantics remain mandatory route blockers. This passive source uses an explicit default palette; it does not claim to capture live desktop themes or system configuration. The desktop's own machine colors come from `machines.toml` instead: `ft mobile export` writes a `.ftworkspace` from it with each machine's resolved theme (see `docs/cli-reference.md`). Both exports set `auto_connect` on every machine and group: opening the workspace on the phone signs every machine in, and a machine's terminal opens when it is chosen.

Configured-alias `ProxyJump` chains expand to at most three ordered transit hops, including each hop's public identities, account, port, and host trust. Unselected hops do not become machines, and transit does not activate their shell preferences. Explicit earlier prefixes override later hops' configured proxies while the first hop's own configured chain is preserved. User/port override syntax, unresolved aliases, repeated hosts, cycles, and excessive depth remain explicit blockers; an unusable chain is never truncated into a usable prefix.

Existing workspace documents support selection of one or more machine groups with their complete route, jump-host, trust, theme, and credential dependencies. Every canonical identity requires an explicit include-private-key or keep-reference-only decision before encryption. The companion accepts matching **OpenSSH Ed25519, ECDSA P-256/P-384/P-521, and RSA 2048–8192-bit key files**, including passphrase protection using **bcrypt with AES-CTR or AES-CBC at 128, 192, or 256 bits**. The companion releases excluded key material and reports concrete omissions and blocked routes. Selection changes invalidate the previous approval, code, and QR presentation.

Optional public points may be absent; passive discovery then requires a `.pub` sidecar and never derives the private identity. Encrypted legacy PEM remains unsupported. Native CryptoKit DER behavior still requires Apple execution.

Mac and iPhone share the exact-byte, domain-separated file comparison value; checking it through a trusted separate channel does not make a self-asserted exporter authenticated. It offers live fountain-coded QR playback with periodic source replay, targeted page repair, 3/5/10-symbol-per-second timing, separately revealed transfer codes, encrypted `.ftairgap` saving, saved **lossless APNG**, and a **verified MP4** path. ## Retained output and session completion

**Search Output** searches canonical rows already retained by the selected terminal, using literal, case-sensitive text on physical screen rows. It neither reads the network nor sends a command. Reads do not move the selected viewport. Search is bounded to 4,096 rows, 4 MiB, 256 pages and 128 matches; the screen reports a reached limit or history changing during the scan. Concealed cells are excluded. Selecting a result revalidates its exact source, geometry, screen, row sequence and matched bytes in the same model transaction that navigates to it. Expired matches remain observations and cannot jump to unrelated output.

The inspection retires the live keyboard before covering the terminal and refuses a late keyboard handoff behind the sheet. **Done** restores the earlier viewing position when its anchors still exist. **Show in Terminal** keeps the selected viewport and offers **Return to Previous View**. A changed or expired bookmark reports failure; it never retargets another terminal. One retained worker owns each search or reveal, and retirement cancels and joins it before model disposal. The preview is a frozen capture of the currently selected received viewport, which can have changed since the match was found.

After a session ends, **View Retained Output** exposes a read-only copy of its last received live viewport, capped at 128 KiB. It is captured after output/input workers settle and before the model is disposed, including when the user had scrolled into older history. It has no model, connection or keyboard authority and uses the same local-only, two-minute-expiring copy policy as Select Output. It remains only in memory until the workspace closes or the controller is replaced. It is not a complete transcript and does not establish that later remote output was received; an incomplete synchronized update is refused explicitly.

Native SSH now reports usable remote exit evidence separately from output EOF and channel closure. Buffered output reaches the model first. After EOF, a readiness-driven two-second window collects a later channel close, nonzero UInt32 exit status or bounded signal name. Each native step reads at most 32 KiB even under continuous control traffic. The pinned libssh2 API cannot distinguish a reported exit status of zero from no exit status, so both remain unknown. Transport loss and local cancellation retain their own reasons. Completion evidence does not resolve the journal's input uncertainty or authorize replay.

The Rust `ft mobile export` / `ft mobile source` path also keeps positive host pins route-specific and unions same-scope revocations across the full inventory, including routes outside a selected group. It reads effective user/global known-hosts files and distinguishes missing sources from unavailable ones. Its bounded passive alias resolver expands unconditional `Include` directives, including `*` and `?` in directory components, in deterministic order within one shared file, byte, depth and traversal budget. Conditional Include/Match, unsupported path substitutions and mandatory source constraints remain route blockers; incomplete includes cannot publish a usable prefix. The repair has independent review, rustfmt parsing/format verification and fixture checks; its Rust regression tests still require the repository's RCH runner.

## Protected SSH authentication

`SSHAuthenticationBroker` implements use of imported Ed25519, ECDSA P-256/P-384/P-521, and RSA-SHA2 identities. A foreground request binds the selected installed-workspace revision, route, account, credential, actual presented host key, transport identity, and original SSH session identifier. The store checks the qualified transport profile, ordered credential policy, complete route dependencies, imported restrictions, protected-key availability, positive host pins, and durable local revocations before allowing a prompt. The same checks run immediately before signing and after the worker returns. Reimport, revocation, cancellation, backgrounding, and protected-storage failure discard delayed results. Request IDs are single-use; one broker owns at most one preparing or signing operation, including a cancelled operation that has not settled.

`SSHUserAuthenticationSigner` constructs the RFC 4252 public-key authentication preimage internally. It offers no arbitrary-message signing API, validates the complete OpenSSH container with the importer's canonical private/public binding checks, and returns the SSH algorithm-tagged signature blob. CryptoKit on Apple and maintained Swift Crypto on Linux perform the existing cryptography; CryptoExtras supplies RSA on both platforms. ECDSA signatures use the required curve-specific SHA-2 hash and canonical positive SSH `mpint` encoding. RSA requires an explicit negotiated `rsa-sha2-256` or `rsa-sha2-512` algorithm while preserving the original `ssh-rsa` key identity and fingerprint. The initial session-identifier profile accepts the 32-, 48-, and 64-byte SHA-2 sizes.

`AppleSSHCredentialSigner` reads only the exact app-owned Keychain account through a fresh user-presence context on one process-wide serial worker. The private container stays within that worker; its results are bounded public identity or signature bytes. Newly imported items retain their verified public blob as nonsecret Keychain metadata, so offering a key does not need a private-key unlock. Older items can derive their public identity through the same bounded protected worker. Public metadata must match the independently stored algorithm and fingerprint; it never authorizes signing. The broker admits up to 32 waiting requests in FIFO order across concurrent connections while retaining one protected worker. Its 60-second deadline includes waiting and confirmation. Cancellation, expiry and backgrounding invalidate queued requests; a cancelled native worker keeps its slot until it settles. The broker rechecks current route and credential authority after waiting. No key file, private-key return API or reusable unlocked-key cache is introduced.

The optional `FrankenTermSSHIntegration.WorkspaceNativeSSHAuthentication` adapter joins this broker to the real libssh2 driver. It checks the actual exchange's host key and negotiated methods, exact endpoint, route revision, credential, transport identity and RFC 4252 challenge before offering or using an imported identity. A suspension/resume cycle retires its foreground witness; durable revocation and reimport invalidate retained authority. Direct SSH and FrankenTerm mux routes support the signing families above, explicit SSH password authentication and bounded keyboard-interactive challenges, including up to three ordered jumps with independent methods at each hop. RSA host keys and credentials must sign with SHA-2. User-certificate offers retain their exact validated certificate binding; host certificates and password changes remain unavailable.

## Implemented invariants

- `WorkspaceStore` serializes the journal, Keychain ownership, and catalog publication under an exclusive persistence lease. Before deleting staged or retired identities, recovery reaffirms the selected catalog's **durability**. Reading renamed bytes after a failed fsync alone does not authorize deletion.
- Import confirmation is tied to an exact decrypted candidate and previously reviewed saved revision. Existing local revocation denies resurrection from an old recording. Missing device keys can be restored from the same backup without duplicating surviving keys.
- The durable catalog remembers accepted bundle/transfer identities, rejects conflicting reuse before staging keys, and requires separate local approval to restore an earlier accepted export. Bundle identities are bound to their exporter across workspaces; transfer IDs and envelope digests cannot be rebound across namespaces. Canonical host-key revocations and mandatory trust requirements survive renamed trust records, replacement, and approved rollback. Migrated transfer identities use the same journal; recovery checks the accepted identity as well as workspace bytes.
- Catalog version four migrates the original single-candidate store, published version-two import history, and published version-three endpoint denials. Every accepted identity, digest, first revision, and global endpoint rejection is preserved. Additional effective-host alias denials and mandatory host-policy requirements survive replacement and approved rollback. The native browser obtains actual Keychain availability and durable local policy in one revision-consistent snapshot, and clears availability on deactivation or protected-storage failure.
- Host-key rejection persists by canonical host and port, independently of imported record IDs. DNS/IDNA, IPv6, and mapped IPv4 spellings cannot remove it. Negative fingerprints take precedence over algorithm labels and positive pins, including a presented certificate authority; certificates themselves still require a future qualified implementation. Every jump hop contributes its own readiness requirements.
- Credential reuse binds both the canonical public fingerprint and algorithm. An import without private material cannot relabel an existing Keychain identity. Matching aliases share material while retaining route-specific candidate order and authentication policy. A blocked candidate does not prohibit a separate permitted candidate.
- Public and encrypted imports reuse compatible protected identities across installed workspaces after checking vault metadata under the same storage lease. Reimporting an unchanged public document can attach a key acquired later while preserving its first acceptance and enforcing the reviewed revision. Replacing one workspace never retires an identity still referenced by another; duplicate private records are not created for shared canonical identities.
- Passive SSH export supports ordinary and OpenSSH v1 hashed `known_hosts`, including nonstandard ports, exact host-key aliases, numeric IPv6 lookup, and revocations. Positive pins require the source lookup to match; negative policy also survives canonical endpoint spelling. Unrelated valid hashes do not disable routes. Malformed hashes, unsupported certificate authorities/markers, and unreadable trust sources cannot silently remove required policy. Source size, alias count, pattern work, and HMAC comparisons are bounded.
- The manifest uses the comprehensive plan's ordered `credential_refs` and `authentication_methods`. Strict core allowlists exclude untyped settings; bounded optional namespaced extensions are discarded before persistence or re-export. Route readiness evaluates every jump, available identities, host pins/revocations and required capabilities independently. The current-plan example is an executable fixture, including mux route policy; this does not implement a mux transport.
- The published catalog contains public manifest bytes and account references, not private containers. `connectLater` remains persisted through restart. Keychain items are device-only, passcode-bound, user-presence protected, nonsynchronizable, and created without overwriting existing accounts.
- `OfflineRestore` distinguishes ciphertext reconstruction, authentication, review, commit, and recovery. Wrong-code retries preserve ciphertext. Suspension discards decrypted previews and retires observation generations. An uncertain publication is reconciled, not blindly repeated.
- Recipient mode binds the exact canonical request ID, public key, advertised envelope limit, and request digest into HPKE setup and the authenticated FTAG header. Unknown modes, malformed headers, wrong requests, over-limit envelopes, and cross-mode fallback are rejected before publication. Only one recipient request exists in a restore actor. Its private key never enters a status, workspace, or persistent store. Backgrounding retains that key only in process memory and requires explicit request resume; close, reset, completed import, or process termination ends its availability. Decrypted review and prior approvals do not survive suspension.
- Native recipient approval binds the complete 32-byte request digest captured by the rendered confirmation control, not merely its displayed abbreviation or a mutable Boolean. The export engine rechecks that digest before sealing. A delayed confirmation, scanner callback, or encryption result cannot silently approve a different destination.
- The HPKE adapter delegates the KEM and key schedule to maintained CryptoKit on Apple and Swift Crypto on Linux. It bounds inputs and performs native X25519 agreement before setup to reject an all-zero result on both sender and receiver paths, including noncanonical low-order aliases. Each local sender context seals once at sequence zero; cancellation cannot return a completed result.
- Recipient envelope caps are checked before allocating an optical receiver. An unrelated destination, wrong mode, or malformed completed envelope discards that selected source and fences its observations while preserving the phone's request for another response. Decrypted packing buffers and owned session keys are cleared where Foundation permits; a private-key copy does not cross the awaited storage-review boundary. This does not guarantee erasure of every copy made by platform cryptography.
- Mac recipient capture uses bounded video buffers and serial Vision QR detection, independent of camera-specific metadata support. It discards late frames, examines at most four frames per second, limits image dimensions and extent, rejects ambiguous requests, and stops after one result or two minutes. Delivery rechecks actual application activity, window attachment, and generation. It records no images or audio.
- Closing the Mac export window clears visible material and the engine's keys, cancels work, and serializes reopening behind final cleanup. Operation identities fence every asynchronous source, key, export, and recording completion. On iOS, protected-storage refreshes run separately from lifecycle transitions, so a delayed catalog read cannot delay suspension or cancellation. Active request display and camera collection keep the screen awake while preserving the user's prior idle-timer setting.
- A QR observation cannot silently change the selected source. Eight bounded strings feed one consumer; there is no task-per-camera-frame fanout. The scanner does not open QR URLs or retain camera images.
- Live playback periodically repeats rotating source fragments while fresh repair sequence numbers continue increasing, so late arrivals can recover even if mixed repair frames are missed. A network change grants dropped or retrying machines three more attempts and replenishes a connected machine's next retry budget. Automatic pane return requires the complete fresh identity described above; restart, replacement and legacy/unavailable identity require explicit selection. If the mux is gone, no shell opens in its place. A direct shell reconnects signed in and waits for **New Session**. Refused credentials and changed host keys never retry; transport failures do, with host verification before each authentication.

Nothing typed before a drop is sent again. A notice distinguishes input that never left the phone, input that may have arrived, and input stopped partway. It remains on that machine through reconnects and new sessions until dismissed. For mux input, uncertainty means the server had not confirmed the write. The pane retains that fact across launches and can disclose it again on return. A killed app similarly discloses unanswered input when that machine next opens. Only the uncertainty is persisted, never the typed content.

Off-screen output marks the machine and pane without changing the selection. **Next New Output** and the fleet overview visit available marked destinations in strip order. Shown panes use server updates; never-shown panes are marked only when successive inventories show scrolling or cursor movement at the same size.
