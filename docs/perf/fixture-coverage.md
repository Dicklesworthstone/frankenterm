# Evidence-stream fixture coverage matrix

Coverage matrix for the `tests/fixtures/evidence-corpus/` JSONL fixtures generated by `scripts/regenerate-evidence-corpus.py`. Substrate for `ft-tf6g3.42` (G54). Consumed by SPRT integration tests (G25 / `ft-tf6g3.10`), conformal-band tests (G26 / `.11`), regime-shift detector tests (G42 / `.27`), causal-DAG attribution tests (G43 / `.28`), Lindley empirical-vs-bound tests (G23 / `.8`), and observed-delay tail tests (G38 / `.23`).

Schema version: `ft.perf.evidence-sample.v1`. Schema spec: [`docs/perf/evidence-stream-schema.json`](evidence-stream-schema.json). Schema evolution: [`docs/perf/evidence-stream-evolution.md`](evidence-stream-evolution.md).

Determinism: every fixture's PRNG seed is `sha256(claim_id || "|" || flavor || "|" || schema_version)[:8 bytes as u64]`. Rerunning `scripts/regenerate-evidence-corpus.py --all` produces bit-identical output, validated by `manifest.json`'s per-fixture `content_hash` field and `scripts/regenerate-evidence-corpus.py --check`.

## Flavor semantics + intended consumer

| Flavor | Ground truth | Intended test scenarios |
|---|---|---|
| `baseline-30d` | `{shift: false, regression: false, tail_class: "light"}` | Stationary baseline. SPRT must NOT flag regression; conformal-band must achieve ≥95% calibration coverage; regime-shift detector must NOT fire. |
| `regression-injected` | `{regression: true, change_point_index: 100, magnitude_pct: 15}` | 15% step regression at sample 100. SPRT must flag regression with confidence; causal-DAG attribution must identify the labeled change point. |
| `regime-shift` | `{shift: true, change_point_index: 100, shift_kind: "mean+variance"}` | 30% mean + 1.8× stddev step at sample 100. Regime-shift detector must fire; SPRT for the same metric must pause for recalibration; conformal-band must trigger recompute. |
| `heavy-tail` | `{tail_class: "pareto-alpha-1.5"}` | Pareto α=1.5: finite mean, infinite variance. Classical Lindley bound must flag the input as out-of-domain (`heavy-tail-out-of-domain` state); the G38 observed-delay tail gate must produce a non-vacuous p99.99 bound. |
| `sparse` | `{below_min_samples: true}` | Single row. SPRT must return `Continue` with `needed_samples` hint; conformal-band must report `recalibrating` state; gates must NOT fabricate a verdict. |

## Per-fixture row schemas

Every row in every fixture validates against `docs/perf/evidence-stream-schema.json` v1:

- Required fields: `schema_version`, `ts_ms`, `claim_id`, `metric_value`, `metric_unit`, `sample_size`.
- Optional fields populated by this corpus: `commit_sha` (the G47 schema-shipping commit `fd89ed378`), `workload_class` (one of `robot-mode-mixed-fixtures`, `fts5-fixture-1k-corpus`, `idle-swarm-200-panes-target-class`, `warm-tier-200-panes-target-class`, `bloom-large-corpus-infrequent-query`), `tags` (`frankenterm_version: 0.0.0-dev`, `fixture_seq: <int>`).
- Optional fields deliberately omitted: `hardware_fingerprint`, `runner_sku` — these are runtime-host-specific and are NOT part of fixture content; consumers that need them in tests can inject via row-level overrides.

## Regeneration workflow

```bash
# Regenerate one claim's 5 flavors (preserves other claims' fixtures + manifest entries):
scripts/regenerate-evidence-corpus.py --claim robot.p95

# Regenerate every claim from scratch (replaces all manifest entries):
scripts/regenerate-evidence-corpus.py --all

# Verify on-disk fixtures still match manifest hashes (CI-friendly):
scripts/regenerate-evidence-corpus.py --check
```

CI gate: a workflow step running `scripts/regenerate-evidence-corpus.py --check` on every PR touching `tests/fixtures/evidence-corpus/**` or `scripts/regenerate-evidence-corpus.py`. Drift = test failure with the specific fixture path + expected-vs-actual hash printed; reviewer must either re-run `--all` and recommit, or justify the drift in the PR description.

## Adding a new claim

1. Add an entry to the `CLAIMS` dict in `scripts/regenerate-evidence-corpus.py` with: `metric_unit`, `baseline_mean`, `baseline_stddev`, `sample_size_per_row`, `workload_class`, `description`.
2. Run `scripts/regenerate-evidence-corpus.py --claim <new-claim>`.
3. Verify `manifest.json` picks up the new entries.
4. Append the new row to the matrix table above (this doc).
5. Cross-reference the originating bead (typically a G19.* child or a new claim) in the description.

## Adding a new flavor

A new flavor is a schema-level extension and requires:

1. Add the flavor key to the `FLAVORS` list in `scripts/regenerate-evidence-corpus.py`.
2. Implement the synthesizer branch in `synthesize()` with the deterministic-seed pattern preserved.
3. Implement `row_count_for`, `label_for`, `ground_truth_for` for the new flavor.
4. Append the column to the matrix table above.
5. Document the flavor's semantics + intended consumer in the "Flavor semantics" table.
6. Cross-link the consumer bead that needs the flavor (so the dependency edge is explicit).
